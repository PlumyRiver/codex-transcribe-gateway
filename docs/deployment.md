# Deployment and credential ownership

Use one Node process or one Compose gateway instance with persistent storage. The browser is needed for initial authorization or an explicitly required reauthorization, not for each transcription.

## Configuration

| Variable | Default / purpose |
|---|---|
| `GATEWAY_TOKEN` | Fresh random client-facing API credential generated by init |
| `CREDENTIALS_KEY` | Independent 32-byte hexadecimal AES-GCM key generated by init |
| `DATA_DIR` | `./data`; encrypted credentials and ownership lock |
| `HOST`, `PORT` | `127.0.0.1`, `8080`; Compose binds internally on all interfaces but publishes host loopback |
| `MAX_CONCURRENCY` | 10, per process |
| `REQUEST_TIMEOUT_MS` | 120000 |
| `UPSTREAM_COOLDOWN_MS` | 300000, process-local failure cooldown |
| `EXPECTED_EMAIL` | Optional account check during a fresh login |
| `EXPECTED_WORKSPACE_ID` | Optional workspace check during a fresh login |
| `GATEWAY_URL` | Optional client CLI destination; HTTPS or loopback HTTP only |

The gateway's API credential and upstream OAuth credentials are different. Never expose OAuth credentials to API callers. Keep `.env` and its encryption key outside images, source control, logs and issue attachments. Keep an encrypted backup and its decryption key separately; losing the key means reauthorization is required.

Login and the server acquire the same persistent ownership lock. The lock is periodically renewed, and abandoned locks expire after approximately 30 seconds. A normal stop releases it. Refresh calls within a running instance are coalesced and a new rotated token is written atomically before callers proceed. Shutdown waits for an active refresh to finish.

This lock protects **one shared directory**, not copied directories or independent hosts. For migration, stop the old owner before restoring the store and key on the new host. Never import your desktop Codex refresh token while the desktop is still refreshing it.

## Restart acceptance

1. Complete your own OAuth login.
2. Transcribe a real recording with known words and verify the text.
3. Restart the gateway, preserving `.env` and the credentials volume.
4. Transcribe the same recording again and inspect `modelVerification`.
5. To observe normal refresh, leave the backend as sole owner until its actual access token approaches expiry. Do not manufacture an expired production credential or fork a refresh grant for testing.

A successful startup/health check is not audio entitlement or model identity evidence.

## VPS versus serverless

The included Compose deployment is intended for a VM/VPS with a persistent volume. An ephemeral filesystem is insufficient for credential rotation and restart persistence. **This release does not implement a Cloud Run/GCS/Secret Manager credential backend.** Do not scale this file-backed image across independent ephemeral instances.

For an existing Sub2API deployment with durable PostgreSQL and Redis, apply the included native patch and retain that deployment's established OAuth storage/refresh owner. See `sub2api.md`. This repository deliberately contains no project-specific cloud resources, service accounts, database passwords or deployment commands tied to the source installation.

## API exposure

Use a TLS reverse proxy for remote API clients. Keep the OAuth callback on loopback plus SSH forwarding. Only share the gateway key with clients you intend to let consume the authorized account's quota. The gateway provides no member billing, tenant isolation or multi-account pool.
